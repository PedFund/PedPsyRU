# Браузерный стенд: задача 01г

Только локальная демонстрация на вымышленных ответах. Не опубликованная платформа для реальных участников. Полная методическая инструкция еще проверяется.

## Запуск

Из корня репозитория с Node.js 22+: `npm start`, затем откройте `http://127.0.0.1:4173`. Внешние пакеты не нужны. Сервер слушает только `127.0.0.1`; публичное размещение не предусмотрено. При занятом порте задайте переменную `PEDPSY_DEMO_PORT` перед запуском. Остановка — Ctrl+C в терминале запуска.

## Сценарий проверки

30 пар/60 альтернатив загружаются из существующего JSON. Каждая пара показывается на отдельном слайде; одновременно видна только одна пара. «Назад»/«Далее» сохраняют выбор, счетчик вопроса отделен от прогресса заполнения. В каждой паре выбирается один вариант; смена A/B не увеличивает число заполненных пар. Кнопка проверки на последнем слайде подсвечивает пропуски; ссылки открывают соответствующие слайды. Неполный бланк не отправляется.

Полный бланк передается серверному `scoreTki`. Технический просмотр показывает пять сырых баллов без нормативов и интерпретаций. Изменение ответа скрывает прежний результат; запрос в работе отменяется, устаревший ответ не отображается. Очистка требует подтверждения. Обновление страницы также начинает заново.

Нативные радиокнопки, подписи, fieldset/legend, заметный фокус, ссылки к ошибкам и адаптивная верстка обеспечивают базовую доступность. Полный аудит доступности пока не выполнен.

## API и хранение

`GET /api/form` возвращает отображаемые тексты и версии, без ключа и исходного каталога. `POST /api/score` принимает существующий версионный контракт с q01–q30 и A/B. HTTP 200 — расчет; 422 — отказ контракта без баллов; 400 — неверный JSON; 413 — тело больше 16 КиБ; 415 — не JSON. Методы и статические пути ограничены списком.

Нет базы, cookies, localStorage, регистрации, авторизации или журнального сохранения ответов. Ответы живут в памяти страницы и обрабатываются локально. API и статика имеют `Cache-Control: no-store`. Ответы не печатаются в журнал и не отражаются в ошибках. Проверяются локальный Host, Origin и cross-site заголовок; это не замена будущей авторизации и аудиту безопасности.

`npm test` — все 31 тест; `npm run test:web` — 16 тестов модели/HTTP. Браузерные сценарии: `WEB_VALIDATION.md`. Следующий шаг — отдельно согласовать модель доступа и сохранение тестового прохождения.
