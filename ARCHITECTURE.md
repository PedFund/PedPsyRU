# Архитектура ПедПси: текущий пилот

Дата: 2026-10-03. Основной репозиторий разработки — `PedFund/PedPsyRU`.

Пилот ниже интегрирован в main через PR #7. Следующая фаза подготовлена в `PHASE2_DESIGN.md`: владелец принял JS/TypeScript + PostgreSQL, сохранение вычислителя, Россию/Selectel и целевые права. Новый сервер/БД и расширенные административные операции еще не реализованы. Автоматические проверки и их границы — `SECURITY_AND_DEPENDENCIES.md`; порядок передачи модели — `PHASE2_HANDOFF.md`. Этот документ продолжает описывать фактический пилот.

## Принятые границы

Каркас 02в: `src/ports` — внутренние async интерфейсы, `src/scoring` — оболочка неизменного JS-core, `src/http` — Fastify без данных, `src/bootstrap` — composition root/loopback 4174. `npm start` по-прежнему запускает прежний пилот 4173. Build в игнорируемый dist копирует ровно необходимые JS/data artifacts побайтово; приложение не исполняет TypeScript напрямую. SQLite/PG адаптеры и перенос HTTP-сценария вводятся следующими задачами. AST guard проверяет типовые/runtime imports и направление зависимостей; не является полным SAST или механизмом проверки научной правильности.

- Текст формы: `methods/tki/form.json`. У каждого пункта устойчивый ID q01–q30; варианты имеют коды A/B и русские подписи а/б.
- Бланк: `methods/tki/BLANK.md`; порядок и тексты совпадают с JSON.
- Расчет: `core/tki-contract.js`; вход не зависит от Excel и языка текста вариантов. Используется только ключ `methods/tki/keys/1.0.0.json` (21A — приспособление, 21B — сотрудничество). Старый ключ и переключение на него удалены.
- Вычислительная формула: существующая `Processor.scoreComplete`, тип `forced`, не переписана. Из копии каталога `methods/builtin.js` удалены ошибочный ключ Томаса—Килманна и его запись описания. TKI вызывается через `scoreTki` с проверенным JSON, не через `Methods.byId`. Другие встроенные обработчики этим пилотом не утверждаются.
- Контрольные примеры: `tests/fixtures/tki-reference.json`; тесты контракта и формы — `tests/`.
- Научная проверка: `METHOD_VALIDATION.md`; успешный расчет не заменяет статус проверки источника.
- Браузерный стенд 01г: `web/index.html`, `styles.css`, `app.js`, `form-model.js`. JSON формы остается единственным источником предъявляемых текстов; передаются только ID и A/B.
- Обязательное требование владельца к предъявлению: каждый вопрос, а в TKI каждая пара A/B, показывается на отдельном слайде. Одновременно виден только один вопрос. Навигация «Назад»/«Далее» сохраняет выбранные ответы, ссылка к пропуску открывает соответствующий слайд; проверка полного протокола доступна на последнем слайде. Порядок вопросов не меняется.
- Локальный транспорт: `web/server.js`, Node.js `http`, только `127.0.0.1`. `GET /api/form` выдает форму и версии; `POST /api/score` вызывает существующий `scoreTki`. Ключ наружу не выдается.
- Ответы и результат демонстрационного `/` живут в памяти, без записи в базу/cookies/localStorage. Отдельный `/access` → `/take` сохраняет собственный учебный черновик в SQLite через защищенный participant API. Диагностические ответы не хранятся в localStorage/cookies. Технический просмотр баллов не является утвержденным индивидуальным отчетом. Этот сервер не определяет производственный стек всей платформы.

## Последующие границы

02г добавляет `src/application/participation.ts` — общий async read/save/complete/result без SQL/HTTP/Node I/O; ID/время/digest и UnitOfWork передаются портами/зависимостями. `src/adapters/sqlite/unit-of-work.ts` — адаптер прежней схемы, только выделенное синтетическое соединение. Внутренний context создается из прежней проверенной participant-сессии и закрепляется WeakMap, подделанный JSON/role не принимается; права повторно проверяются внутри транзакции. Очередь сериализует callbacks; nested/использование ports после commit запрещены. CAS, result/completed и audit атомарны; пропущенный mandatory audit блокирует commit. Старые storage services/миграции и HTTP-пилот не меняются. `OutboxRepository` остается будущим контрактом, вызов SQLite реализации явно запрещен, никакой тихой доставки. Контрактные тесты определены один раз для будущей проверки обоих движков. Denial/CSRF/Origin/HTTP mapping нового API относятся к 02з; тип внутреннего контекста сам по себе не авторизация.

01д.1 подготовила схему/матрицу/контракт. 01д.2 создала storage/: SQLite, миграции, пакет TKI, seed и 22 теста. 01д.3а добавила storage/access.js, миграцию 002, web/access-routes.js и /access. 01д.3б добавила миграцию 003, storage/roles.js, admin-access.js, web/admin-routes.js и /admin. Обе staff-роли имеют глобальное чтение/скачивание, не зависят от study_memberships. Staff и participant имеют разные hashed-session tables и host-only HttpOnly Strict cookies; проверки выполняются сервером на каждом запросе. Общие криптографические примитивы переиспользуются, области не смешиваются. CLI выдает staff-credentials только интерактивно; auto admin/password нет.

Протокол читает тексты из закрепленного release_items, не из текущей формы. JSON-export — согласованный синхронный снимок и обязательный метаданный аудит до выдачи тела; лимиты 500 протоколов/4 MiB, без молчаливого усечения. Не экспортируются ключ, source_text, hashes, секреты или scores. Файл SQLite не выдается HTTP/Git. Вычислитель неизменен. 134 теста — ACCESS_VALIDATION.md, ADMIN_VALIDATION.md, DRAFT_VALIDATION.md и COMPLETION_VALIDATION.md. Управление исследователями/методиками еще не реализовано, policy-права отделены от runtime capabilities.

01д.4: storage/drafts.js отделяет сохранение от вычисления. Индивидуальная сессия → текущие доступность/область → строгий снимок → BEGIN IMMEDIATE → повторная проверка + CAS revision → ответы/слайд/revision + обязательный аудит → commit. Нет нового выпуска, попытки или результата. web/draft-model.js последовательно отправляет снимки, подтверждает только отправленное поколение; конфликт/таймаут блокируют запись до явного перечитывания. web/draft.js предъявляет закрепленную форму по одной паре. Служебные роли не записывают от имени участника. Новая миграция не нужна.

Реализованный поток 01е: индивидуальная сессия → проверка области/назначения → сохраненный полный снимок/expected_revision → существующий `scoreTki` с закрепленным выпуском → атомарные result/completed/revision/mandatory audit. storage/completion.js не принимает клиентские ответы/баллы/версии. Повтор completed возвращает сохраненный payload без перерасчета; GET result только своему участнику. UI подтверждает необратимость и дожидается очереди записи; reload/вход восстанавливают raw result. Ключ клиенту не выдается, интерпретации не добавлены. Только demo. Среда: Node.js 22.17.1, экспериментальный node:sqlite / SQLite 3.50.0; выбор только учебный, без production-готовности. Миграции/вычислитель неизменны. Детали — COMPLETION_VALIDATION.md и storage/README.md.

Участник выбирает вариант по коду, а интерфейс отправляет `{item_id, value}`. Текст вопроса и подпись а/б не участвуют в подсчете баллов. Версии текста формы, ключа и вычислителя фиксируются раздельно.

Таблицы исследований/групп/этапов/назначений созданы, доменный конструктор еще не реализован. Вход участника и административное чтение/скачивание реализованы. Согласия, manager CRUD и production-стек — нет. Развертывание сайта и интеграция форм не определяются этим пилотом.

## Ограничения

Контракт поддерживает одну методику и только исправленный ключ 1.0.0 с обработчиком `tki-contract-0.3.0`. Ключ 1.0.0 проверен, допустимые полностью заполненные сырые результаты имеют `usable_for_aggregation: true`. Запросы с удаленной или неизвестной версией отклоняются без баллов. Подмена ключа под прежним ID блокируется проверкой digest. Полное утверждение инструкции и методики учитывается отдельно; формальные JSON Schema для универсального контракта и редактора библиотеки предстоит утвердить отдельно.
