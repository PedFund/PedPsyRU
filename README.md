# PedPsyRU
Информационно-аналитическая платформа организации, проведения и анализа психолого-педагогических исследований

**Текущая точка: фаза2 завершена, 8 из 8 задач в main.** Типизированный backend, PostgreSQL/RLS, проверенный перенос и restore, защищенный участнический API с прежним TKI. Это synthetic техническая основа, не законченная production-платформа. [Приемка](PHASE2_ACCEPTANCE.md), [статус](STATUS.md), [следующие небольшие задачи03а–03з](BACKLOG.md).

Новый APIv2 включается только через явно подготовленный synthetic PostgreSQL loopback профиль: `npm run build`, `npm run start:platform:demo`. Без PEDPSY_PG_DEMO/валидных PGHOST/PGPORT/PGDATABASE/PGUSER/PGPASSWORD изenv он отказывается запускаться; ни миграции, ни seed, ни accounts автоматически не создаются. `start:platform` остается health-only4174; текущий браузер4173 —прежний пилот. Реальное размещение Selectel/данные/MFA менеджеров —отдельные задачи.

Первый небольшой этап — бланк и вычислительный контракт Томаса—Килманна. Общий бланк для мужчин и женщин создан из текста владельца проекта; грамматические формы отвечающего объединены через `/`.

Точные Fastify/pg/TypeScript закреплены в lockfile/SECURITY_AND_DEPENDENCIES. `npm test` выполняет build и 179 основных тестов. `npm run test:pg` требует явной временной PostgreSQL-среды; обязательный CI проверяет 38 реальных PG/API/backup сценариев, без скрытых пропусков. node:sqlite остается учебным контуром.

Ключ [1.0.0](methods/tki/keys/1.0.0.json) исправлен по подтверждению владельца: **21A — приспособление, 21B — сотрудничество**. Все 60 альтернатив совпадают с контрольным ключом, каждая шкала содержит 12 пунктов. Новые вызовы `scoreTki` используют версию 1.0.0, старый ошибочный ключ удален, переключения на него нет. Полная инструкция и утверждение методики остаются отдельной задачей.

Браузерный стенд: `npm start`, затем `http://127.0.0.1:4173`. Каждая пара A/B — отдельный слайд. `/` — несохраняемая демонстрация с техническим просмотром сырых баллов; обновление очищает ее. `/access` → назначение → `/take` — отдельное учебное прохождение: ответы и текущий слайд автоматически сохраняются в SQLite и восстанавливаются после входа. Состояние записи видно; конфликт вкладок не перезаписывает чужое обновление. Полный сохраненный протокол завершается после подтверждения: один неизменяемый результат с пятью raw шкалами, без интерпретаций; reload/вход возвращают тот же результат. Только вымышленные данные; пилот интегрирован в main через PR #7. Новая основа фазы2 также в main через #8–#14; прежний интерфейс4173 автоматически не переключался.

Приемка фазы2: **179 основных + 38 PostgreSQL тестов** успешны, все 6 GitHub jobs зелёные (run37130462614/head5b42cce7). `/admin` — обе административные роли, просмотр/контроль статусов и скачивание первичных ответов **всех исследований** в JSON, с аудитом. Администратор не обрабатывает/дополняет методики; суперадминистратор — менеджер исследователей и методик. Управление исследователями/редактор методик пока отдельные будущие задачи.

Индивидуальные вымышленные credentials выдаются только в своем интерактивном терминале: `npm run auth:issue -- 1 DEMO-001`; для администратора `npm run staff:issue -- administrator PLATFORM-ADMIN`, для суперадминистратора `npm run staff:issue -- superadministrator PLATFORM-SUPERADMIN`. Универсального пароля и auto accounts нет, секрет показывается один раз. Порядок reset/revoke и ограничения — ADMIN_VALIDATION.md. Это команды прежнего локального учебного контура. Его парольный staff-вход не заменяет обязательную MFA будущей платформы и не разрешает реальные данные. Следующая задача —03а из BACKLOG, затем administrative login/MFA и кабинеты; новых manager accounts/рассылки/production автоматически не создаем. Реального набора/публичного размещения нет.
