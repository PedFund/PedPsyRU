# МетодТест

Информационно-аналитическая платформа для организации, проведения и анализа психолого-педагогических исследований. Репозиторий сохраняет совместимые технические идентификаторы `pedpsy`, но пользовательское название платформы — «МетодТест».

- [CURRENT_STATE.md](CURRENT_STATE.md) — краткое фактическое состояние веток, PR, CI и открытых вопросов.
- [AGENTS.md](AGENTS.md) — действующие правила работы coding agents.
- [methods/README.md](methods/README.md) — единая точка входа в библиотеку методик.

- [ARCHITECTURE.md](ARCHITECTURE.md) — архитектурные границы платформы.

## Ветки и контуры

`main` – основная интегрированная ветка. Кабинет исследователя, библиотека учебных выпусков и доработки пользовательских сценариев вошли через [PR №67](https://github.com/PedFund/PedPsyRU/pull/67). Проверенный интеграционный коммит: `b3a4f190454de2ab8bf9882430f731ef7f114769`; [итоговый CI `main`](https://github.com/PedFund/PedPsyRU/actions/runs/41617936028) успешно завершил 6/6 заданий. PR №64 закрыт как уже включенный в код; №65 закрыт без Merge как устаревший документальный срез. Свежее состояние проверяйте в [CURRENT_STATE.md](CURRENT_STATE.md) и на GitHub.

Локальные контуры разделены:

- `npm run start:platform:ui` — просмотр интерфейса на `http://127.0.0.1:4175/workspace` без PostgreSQL; API отвечает 503 и не имитирует успешное хранение.
- `npm run start:platform:demo` — синтетический PostgreSQL-контур на loopback при явно подготовленной конфигурации и MFA-ключе.
- прежний учебный пилот на 4173 сохраняется отдельно и автоматически не переключается.

Не публикуйте локальный стенд и не вводите в него реальные данные. Размещение в Selectel, реальные учетные записи, почта, key custody и эксплуатационная приемка — отдельные задачи.

## Что уже есть в кодовой базе

Платформа включает типизированный backend, PostgreSQL/RLS, аудит и CAS, персональные и staff-сессии с MFA, кабинеты, конструктор исследований, группы, этапы, назначения методик, приглашения, сведения об участниках, сохранение прохождения и результатов. Перечисленные компоненты вошли в `main` через интеграцию №67, но успешные синтетические тесты не равны производственной приемке. Исследователь принимает одноразовое приглашение по ссылке и сразу входит в кабинет; административный вход по-прежнему защищён паролем и MFA.

Библиотека содержит сохраненный архив и отдельный набор назначаемых учебных выпусков. Сейчас в учебном каталоге **23 назначаемых выпуска**, включая 10 из `methods/approved/v1`; целевые 11 пилотных методик подключены (10 выпусков `approved/v1` + TKI), последний подключённый — Мотков-18. Архивное наличие, техническая готовность и научно-правовое утверждение не равнозначны. Подробности и источники — в [methods/README.md](methods/README.md).

## Подключение новых методик

Платформа должна регулярно расширяться без переделки общего ядра. Владелец-суперадминистратор допускает добавление методик **через код**, без обязательного визуального no-code конструктора. Обычные опросники используют проверенные общие адаптеры, нестандартные задания – отдельные версионированные программные модули. Подробнее: [METHOD_EXTENSION_CONTRACT.md](METHOD_EXTENSION_CONTRACT.md) и [methods/README.md](methods/README.md).

Для каждого нового выпуска требуется проверка цепочки **каталог → назначение → прохождение → сохранение → обработка → результаты → доступная проекция/экспорт**. Новые ключи и формы не заменяют ранее закрепленные версии. Реестр и открытый контракт модулей существуют, однако универсальный онлайн-маршрут для любых нестандартных форм и автоматическая загрузка через суперадминистратора еще не завершены. Научный и правовой допуск отдельны от технической регистрации.

## Целевая эксплуатация: Selectel

Решение владельца – разместить **приложение МетодТест и рабочую PostgreSQL в Selectel** как раздельные компоненты. История Git и PR остается в GitHub; в рабочий контур передаются проверенная сборка, нужные артефакты и миграции. Данные исследований хранятся в PostgreSQL, резервные копии и восстановление обязательны. Конкретный тип PostgreSQL в Selectel еще не выбран; эксплуатационный деплой не выполнен и не разрешается самим фактом Merge.

## Разработка и проверки

Требуется Node.js не ниже 22.17.1; CI проверяет Node 22 и 24.

```text
npm ci --ignore-scripts --no-audit --no-fund
npm run build
npm run typecheck
npm run check:architecture
npm run check:syntax
npm run check:dependencies
npm test
```

`npm run test:pg` разрешено запускать только против явно выделенной синтетической PostgreSQL. Не очищайте и не пересоздавайте рабочую локальную базу. Перед merge нужны все обязательные проверки точного head, включая PostgreSQL, браузерные E2E, зависимости и секреты.

## Научные и эксплуатационные границы

- Не изменяйте закрепленные формы, ключи, шкалы, нормативы и исторические результаты без отдельной методологической проверки.
- Не запускайте код из архивных материалов и не делайте архивный тест назначаемым автоматически.
- Используйте только синтетические данные в разработке и CI.
- Технически работающий учебный выпуск не означает научного утверждения, разрешения публикации или готовности к сбору реальных данных.
- Merge в `main`, обновление рабочего PostgreSQL и развертывание выполняются только по отдельному разрешению владельца.
