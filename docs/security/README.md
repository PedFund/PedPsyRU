# Безопасность и соответствие РФ

Каталог документов по безопасности платформы МетодТест. Код не меняется: это контрольные точки, обоснования и планы, на которые опираются последующие технические задачи.

## Документы

| Документ | Что фиксирует | Статус |
|---|---|---|
| [DATA_INVENTORY.md](DATA_INVENTORY.md) | инвентаризация ПДн: где лежат, правовые основания, копии, сроки хранения, доступ, пробелы | черновик, требует подтверждения владельцем |
| [UVZ_DRAFT.md](UVZ_DRAFT.md) | обоснование УЗ-3 по ПП № 1119, тип угроз, требования пп. 13–14, план | проект акта, утверждает оператор |

## Ключевые выводы

- Категория ПДн — иные (данные о здоровье не обрабатываются), субъекты не сотрудники, менее 100 000, ГИС/КИИ нет.
- Уровень защищённости — **УЗ-3** (ПП № 1119, п. 11 «б») при угрозах 2-го типа; УЗ-1 возникнет только при признании актуальными НДВ в системном ПО.
- Требуются организационные действия: ответственное должностное лицо (п. 14), перечень лиц с доступом (п. 13 «в»), документы по помещениям, носителям и СЗИ.
- До реальной обработки ПДн нужны реальные тексты согласий/уведомлений: сейчас схема допускает только `synthetic_only`.

## Ближайшие задачи (по приоритету)

1. Инвентаризация и акт УЗ — этот каталог.
2. Модель угроз и базовая оценка зрелости У_зи (методика ФСТЭК от 07.08.2026).
3. Матрица мер по приказу ФСТЭК № 21 для УЗ-3 (с учётом проекта нового приказа).
4. Технические аудиты: аутентификация и сессии, управление доступом и RLS, аудит/логи без ПДн.
5. Процесс: SSDLC по ГОСТ Р 56939-2024, реагирование на утечку (24/72 ч по 152-ФЗ), резервирование и восстановление.

## Правила работы

Любое изменение — ветка → commit → push → PR → CI → отдельное разрешение владельца на Merge. В документах и примерах только синтетические данные; реальные email, ответы, результаты, ключи и секреты не публикуются.
