# Закрытый пилот на 200 участников: вход и регистрация

Статус: **закрытый synthetic-пилот на стенде**. Реальные персональные данные, юридические тексты и отправка писем не включены. Почта используется только как логин; подтверждение и восстановление доступа выполняет куратор вручную.

## 1. Что меняется в лимитах

Без явной настройки действует прежний production-default:

- 30 попыток входа участника за 5 минут (общий bucket);
- 5 попыток на один код и 5 на один email за 15 минут;
- одна одновременная scrypt-операция; при занятости — сразу `LOGIN_THROTTLED`.

Пилотный профиль включается **только** переменной `PEDPSY_PILOT_LOGIN=1`:

```text
PEDPSY_PILOT_LOGIN=1
# необязательно, значения проверяются при старте:
PEDPSY_PILOT_LOGIN_LIMIT=900        # 31..1200, по умолчанию 900 попыток / 5 минут
PEDPSY_PILOT_LOGIN_CONCURRENCY=2    # 1..4, по умолчанию 2
```

В пилотном профиле:

- вход по коду и вход по email делят один общий bucket: 900 попыток / 5 минут;
- регистрация по групповой ссылке имеет отдельный bucket: 900 / 5 минут;
- персональные лимиты 5/15 минут на код, email и браузер **не меняются**;
- до 2 паролей хешируются одновременно, до 512 запросов ждут в очереди не дольше 30 секунд; сверх этого — `THROTTLED`;
- запросы, которые ждут очередь, не получают мгновенный 429; это и есть основное исправление для одновременного старта.

Проверка конфигурации fail-closed: неизвестное значение `PEDPSY_PILOT_LOGIN`, лимит вне диапазона или установленный override без режима останавливают приложение с `PILOT_LOGIN_CONFIG_INVALID`.

## 2. Email как логин

Для реальных адресов на стенде нужны одновременно:

```text
PEDPSY_CONTACT_DEMO=1
PEDPSY_PILOT_REAL_EMAIL=1
PEDPSY_PILOT_LOGIN=1
```

`PEDPSY_PILOT_REAL_EMAIL=1` разрешает регистрацию и вход с реальным адресом, но письма не отправляются. Ссылка-приглашение и подтверждение передаются вручную.

Локальная часть адреса сохраняет регистр (`Real.Person@example.org` и `real.person@example.org` — разные ключи). Участнику нужно вводить тот же адрес, что при регистрации; куратору — проверять это при ручном подтверждении.

## 3. Ожидаемая нагрузка на стенде

Стенд: 2 vCPU, 4 ГБ RAM, без swap. Один scrypt-хеш требует около 128 МБ памяти. При `PEDPSY_PILOT_LOGIN_CONCURRENCY=2` одновременно считаются два пароля на входе и два на регистрации; пик памяти — около 512 МБ. Очередь ограничена, поэтому всплеск на 200 человек не приводит к массовому 429.

Рекомендации на старт:

- просить участников входить в течение 15–30 минут, а не в одну минуту;
- на 200 человек при 2 попытках на человека это около 400 попыток — ниже 900;
- если пришло больше 512 одновременных ожиданий, часть получит `LOGIN_THROTTLED`; это защита, а не сбой;
- при массовых ошибках пароля проверять `PEDPSY_PILOT_LOGIN_LIMIT`, но не поднимать выше 1200 без отдельного решения.

## 4. Проверка после включения

```bash
systemctl restart mettest
curl -fsS http://127.0.0.1:4174/health
```

Полезные запросы (только синтетический контур; пароли и токены не выводить):

```sql
-- общий bucket входа и регистрации
SELECT bucket_hash,count,window_start_ms FROM pedpsy.login_throttles
ORDER BY window_start_ms DESC LIMIT 20;

-- отказы по лимиту за последний час
SELECT action,reason,count(*) FROM pedpsy.access_audit_events
WHERE at_ms > (extract(epoch FROM clock_timestamp())*1000 - 3600000)::bigint
  AND reason='LOGIN_THROTTLED' GROUP BY action,reason;
```

Smoke на 200 участников выполняется на синтетических аккаунтах: 200 последовательных/параллельных попыток входа не должны получать `LOGIN_THROTTLED`, а 31-я попытка без пилотного режима — должна.

## 5. Откат

Удалить `PEDPSY_PILOT_LOGIN=1` (и pilot-override) из `/etc/mettest/app.env`, перезапустить сервис. Приложение вернётся к 30 попыткам / 5 минутам и single-flight; уже поставленные в очередь запросы завершатся, новые будут получать 429 как раньше. Миграция `087` append-only и отката схемы не требует: старые функции не изменены.

## 6. Что ещё не решено

- Реальная отправка писем (Selectel Mail) не подключена.
- Автоматическое восстановление пароля по почте невозможно; до появления провайдера действует ручной сброс доступа куратором/администратором с аудитом.
- Юридические тексты, этика и приёмка реальных данных остаются блокером для пилота с реальными ПДн.
