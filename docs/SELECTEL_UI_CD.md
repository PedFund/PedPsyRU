# Selectel UI CD – непрерывная публикация косметических изменений

Статус: **подготовленная конфигурация, требующая одноразовой настройки Selectel и GitHub**.
Не означает, что функция включена или опубликована. Отдельная задача от оркестрации PR #205.

## Зачем и как работает

- После **успешного полного `PedPsy CI`** на точном HEAD защищенной `main` запускается `Selectel UI CD`.
- Workflow сверяет текущий Git SHA сайта из `<app_root>/.mettest-deployed-git-sha` с репозиторием и анализирует **все изменения с реально опубликованной версии до актуальной main**, а не только последний коммит.
- Разрешен ровно один тип изменения: модификация `web/workspace/styles.css`. Новые/удаленные CSS, HTML/JS, backend, права доступа, методики, миграции, конфигурация и документы **не публикуются автоматически**.
- Сверяются SHA-256 старого CSS на сервере и нового CSS из проверенного коммита.
- CSS переносится по SSH, сохраняется предыдущая копия, обновление выполняется через атомарное переименование, затем перезапускается служба Node.js, потому что `workspaceAssets()` читает файлы при запуске.
- Проверяются `https://mettest.vibemind.pro/health` и SHA-256 опубликованного CSS. При неуспехе предыдущий CSS восстанавливается и служба перезапускается.
- Записывается новый опубликованный SHA. Если версия сервера неизвестна/не соответствует ожидаемой, workflow прерывается **до изменения файлов**.

В GitHub нет автоматического деплоя для `main` с миграциями. Первичная публикация текущей `main` с изменениями PR #200–#202 требует отдельного контролируемого выпуска.

## Что подготовлено

- `.github/workflows/selectel-ui-cd.yml`: workflow-run после успешного `PedPsy CI` или ручной `check` / `deploy`.
- `scripts/selectel-ui-cd-check.mjs`: анализ diff опубликованного SHA до целевого SHA; исключает накопленные изменения других компонентов.
- `scripts/selectel-ui-remote.sh`: read-only status и транзакционная CSS-замена с резервной копией/автоматическим rollback.
- `tests/selectel-ui-cd.test.js`: тесты позитивного и блокирующих сценариев, bash syntax check.
- Никаких секретов, ключей, паролей и фактических адресов серверов (кроме публичного домена) в Git.

## Разовая настройка владельцем/администратором после Merge конфигурации

### 1. Проверить рабочий Selectel

Администратор входит в Selectel и через SSH определяет фактические:
- путь корневого каталога приложения (может отличаться от примера в `docs/PRODUCTION_RUNBOOK.md`);
- имя systemd-службы, работающей с Node.js;
- пользователя службы, владельца `web/workspace/styles.css`;
- точный Git SHA версии приложения, **которая действительно опубликована**;
- наличие `sudo -n systemctl restart <service>` и `sudo -n systemctl is-active --quiet <service>` у отдельного пользователя деплоя;
- отсутствие симлинков в каталоге приложения и в CSS, путь под `/opt/`.

**Не угадывать SHA по последнему CI в GitHub.** Код на Selectel обновляется отдельно.
Для опубликованной версии установить `<app_root>/.mettest-deployed-git-sha` только после проверки ее соответствия реально работающему коду. Дать доступ на чтение/запись файла пользователю деплоя.

Если приложение устанавливалось не из Git и точную версию подтвердить нельзя, выполнить отдельный контролируемый полный релиз с резервной копией, затем зафиксировать его SHA.

### 2. Организовать отдельный ограниченный SSH-доступ

Создать отдельный ключ для технического пользователя деплоя, **без root-доступа по SSH**.
Дать ему минимальные права на обновление только CSS, создание контрольной точки и штатный перезапуск конкретного systemd-сервиса. Не предоставлять доступ к PostgreSQL, секретам приложения, бэкапам и другим файлам.
Проверить fingerprint SSH host key по независимому защищенному каналу; сохраненный `known_hosts` должен совпадать с реальным хостом, без отключения проверки.
Подключение к Selectel по SSH описано в официальной документации Selectel. Порт и имя хоста берутся из фактической конфигурации, не угадываются.

### 3. Настроить защиту GitHub

`PedFund/PedPsyRU → Settings → Rules → Rulesets` (или `Branches`) для `main`:
- требовать Pull Request и успешный `Required checks` (и связанные обязательные тесты);
- требовать обновления ветки относительно текущей `main` перед слиянием;
- запретить force push и удаление `main`;
- настроить запрет обхода правил администраторами/ботами, насколько позволяют настройки репозитория.

Workflow проверяет `branches/main.protected=true` на старте. В текущем состоянии (23.11.2026) ветка не была защищена, поэтому CD безопасно откажется работать до этого шага.

### 4. Подключить GitHub Environment

`Settings → Environments → New environment → selectel-ui`.

Environment разрешить только для ветки `main`. В разделе **Environment secrets** сохранить:
- `SELECTEL_UI_SSH_KEY`: закрытый ключ **отдельного** SSH-пользователя деплоя;
- `SELECTEL_UI_KNOWN_HOSTS`: проверенная строка `known_hosts` для сервера (с портом при нестандартном SSH).

В `Settings → Secrets and variables → Actions → Variables` указать:
- `SELECTEL_UI_HOST`: фактический SSH-адрес сервера;
- `SELECTEL_UI_USER`: ограниченный пользователь деплоя;
- `SELECTEL_UI_PORT`: SSH-порт, обычно 22, но нужно проверить;
- `SELECTEL_UI_APP_ROOT`: фактический абсолютный каталог приложения под `/opt/`;
- `SELECTEL_UI_SERVICE`: фактическое имя systemd unit;
- `SELECTEL_UI_AUTODEPLOY`: **пока оставить пустой/false**.

Никогда не публиковать значения секретов и приватные ключи в PR, комментариях или этом чате.

### 5. Контролируемый первичный релиз и активация

Текущая main содержит изменения из PR #200, #201, #202, включая миграцию для `display_name`. Отдельно ожидается PR #204 с исправлением MAIA-R; он не входит в main автоматически. Эти изменения **не подпадают** под CSS-only CD.

Сначала необходимо:
1. проверить миграции и совместимость с уже работающей PostgreSQL;
2. сохранить и проверить резервную копию перед разрешенным полным выпуском;
3. по отдельному разрешению выполнить штатный полный релиз на Selectel;
4. подтвердить фактический новый SHA на сервере, записать marker;
5. выполнить одну синтетическую косметическую CSS-задачу через PR, все проверки, тестовую автоматическую публикацию и rollback rehearsal;
6. только после успеха включить `SELECTEL_UI_AUTODEPLOY=true`.

При отсутствии marker или его несоответствии опубликованному коду деплой блокируется.

## Где смотреть владельцу

- **GitHub → Actions → PedPsy CI**: прошла ли сборка и проверки.
- **GitHub → Actions → Selectel UI CD**: блок `Verify exact main and green CI`, затем `Publish CSS-only to Selectel`.
- **GitHub → Environments → selectel-ui**: статус GitHub Deployment и ссылка на сайт.
- **Сайт**: https://mettest.vibemind.pro/workspace; после публикации обновить браузер Ctrl+Shift+R.
- Для надежной проверки CSS: шаг `Install, restart, verify public site` сверяет публичный контент по SHA-256 и пишет старый/новый commit SHA в `GITHUB_STEP_SUMMARY`.

Зеленый PR-CI **не означает**, что сайт обновлен. Только успешный `Selectel UI CD` и фактическая проверка CSS подтверждают публикацию.

## Остановка и ограничения

- Быстрая остановка: поменять `SELECTEL_UI_AUTODEPLOY` на `false` или удалить переменную.
- Все деплои выполняются последовательно. После ошибки изменения CSS автоматически отменяются; журналы GitHub сохраняют причину.
- Внешний DNS/TLS/CDN и кэш браузера могут влиять на видимый результат; система использует уникальный query-параметр для проверки CSS.
- Это пока только **CSS-CD**, а не автоматическая публикация форм, методик, JavaScript, HTML или Node.js.
- Не изменять этим механизмом реальную PostgreSQL, не импортировать методики и не запускать нагрузочные тесты на production.
