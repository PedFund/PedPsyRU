## Что работает

- Миграция 002: participant_credentials, participant_sessions, login_throttles, access_audit_events. Старую 001 не изменяли. FK связывают credential/session с одним участником и исследованием, identity нельзя подменить или REPLACE.
- Пароль: стандартный Node.js scrypt, N=131072, r=8, p=1, dk=64, maxmem=160 MiB, уникальная случайная соль 16 байт. Пароль 12+ символов, максимум 256 UTF-8 байт, без молчаливого обрезания/нормализации. Сравнение хэшей timingSafeEqual; для неизвестного кода также выполняется дорогой расчет. Поиск кодов/сессий и области — параметризованный SQL. Код входа глобально уникален, не равен display_code как разрешению доступа.
- Сессия: случайный токен 32 байта, в SQL только SHA-256. Абсолютный срок 30 минут, бездействие 10 минут; UTC epoch ms. HttpOnly/SameSite=Strict, host-only cookie. В JSON нет session token. Повторный вход с прежней cookie отзывает прежнюю сессию, не создает новые попытки. Остальные независимые сессии остаются до срока/отзыва; сброс пароля/отзыв credential прекращают все его сессии.
- При каждом запросе проверяются credential version/status, participant/study, demo, срок/отзыв. Чтение попытки дополнительно проверяет enrollment, assignment, group/stage и их доступность. SQL scope берется из проверенной сессии, не из роли/ID клиента. Чужой и отсутствующий ID одинаково дают 404 NOT_AVAILABLE; отсутствие сессии — 401 AUTH_REQUIRED.
- Для login/logout требуется точный Origin. Logout также требует связанный с токеном CSRF через X-CSRF-Token; он выводится HMAC-SHA-256 от session token и не позволяет восстановить token. Сохранились Host/Origin/Sec-Fetch-Site/CSP/no-store ограничения стенда; CORS не открыт.
- Сохраняемый в SQL limiter: 5 попыток на код за 15 минут и 30 общих за 5 минут (включая успешные, неизвестные и ошибочные); только один scrypt одновременно на экземпляр службы. Перезапуск не сбрасывает счетчики. Старые окна очищаются, в таблице только хэши buckets. Это локальный пилотный limiter, не production-защита от DoS.
- Аудит: время, credential/study ID при подтвержденном акторе, действие, allow/deny, код причины. Нет паролей, cookie, CSRF, тел запросов, ответов/баллов; append-only SQL. Нет открытого endpoint аудита.

Выбор scrypt при отсутствии Argon2id в текущем runtime и параметры сверены с [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html); API/ограничения памяти — с [Node.js 22.17.1 crypto](https://nodejs.org/download/release/v22.17.1/docs/api/crypto.html). Cookie/сроки/отзыв учитывают [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html). Это ориентиры реализации, не сертификат безопасности.

## API и интерфейс

| Маршрут | Доступ | Результат |
|---|---|---|
| POST /api/auth/login | Строгий JSON login_id/password, same-origin | HttpOnly cookie, CSRF, срок; никаких клиентских ролей/scope |
| GET /api/auth/session | Действующая сессия | Свой display_code, роль participant, срок, CSRF |
| POST /api/auth/logout | Сессия, Origin и CSRF | Серверный отзыв, очистка cookie |
| GET /api/participant/attempts | Сессия | Только свои доступные попытки/версии/статусы |
| GET /api/participant/attempts/:id | Своя доступная попытка | Существующий снимок, qXX, revision, ответы; без результата/ключа/digests |

Новый `/access` показывает вход и статусы T0/T1/T2. На главной странице ссылка на вход. Форма TKI по-прежнему предъявляет одну пару на слайде, остается несохраняемым демонстрационным бланком. POST/PUT/PATCH/DELETE черновика, завершение и скачивание в participant API не открыты. Нельзя называть GET состояния автосохранением или обещать продолжение UI. `/api/score` — прежний stateless расчет вымышленного запроса, не чтение чужого результата.

Если учебной базы нет, сервер не создает ее автоматически, защищенные API возвращают 503 ACCESS_NOT_CONFIGURED. При подготовленной базе npm start проверяет/применяет append-only миграции. Работает только 127.0.0.1. При ошибке схемы старт не открывает защищенный контур.

## Локальная выдача, сброс и отзыв

Из корня проекта **в интерактивном терминале владельца**:

```text
npm run db:seed
npm run auth:issue -- 1 DEMO-001
npm start
```

Открыть http://127.0.0.1:4173/access. CLI выдаст S1-DEMO-001 и уникальный случайный пароль один раз. Для второго исследования — `2 DEMO-001`. Пароль не передается аргументом/URL и не пишется в файл. Без TTY CLI отказывается выдавать секрет в tool/log output. Аккаунты не создаются при seed или запуске сервера, универсального пароля нет. Повтор issue не перезаписывает credential.

```text
npm run auth:reset -- 1 DEMO-001
npm run auth:revoke -- 1 DEMO-001
```

Reset генерирует новый пароль и прекращает старые сессии, не удаляет участника/ответы. Revoke закрывает вход/сессии. Это полномочие локального владельца вымышленной базы, не сетевой endpoint восстановления, не административная роль пользователя платформы. Реальное восстановление требует проверки личности и отдельного workflow.

## Ограничения и следующий шаг

Это не независимый аудит безопасности. Cookie без Secure допустима **только в этом loopback HTTP-пилоте**; для публичного сервера обязательны HTTPS/Secure и отдельная проверка. Cookie host-only, но не изолирована по порту: не запускать недоверенные сервисы на том же host. Владелец файла/машины вне модели удаленного API; шифрование диска, MFA, production-лимиты, защита хостинга, юридические основания/согласия, сроки хранения и надежное восстановление не готовы. Обращение к исключенному участнику отвергается по текущему статусу; отдельного постоянного отзыва при исключении пока нет.

**Последующее уточнение владельца и 01д.3б:** обе административные роли вправе видеть/скачивать все исследования без разового grant; это реализовано в отдельном staff realm, не participant API. Администратор — менеджер исследователей без обработки/дополнения методик; суперадминистратор — менеджер также методик. ADMIN_VALIDATION.md фиксирует 21 новый тест и реальные скачанные JSON. В основном файле auto credentials нет; participant не может назначить себе роль. Следующий 01д.4 — запись/восстановление черновика.
