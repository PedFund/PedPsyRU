### Свидетельства и обнаруженные расхождения

1. Локальный `keys/13_tki_r.md` совпадает с исполняемым ключом и одновременно указывает диапазон `[0,12]` для каждой шкалы. Фактические максимумы legacy: 12, 12, 12, **13**, **11**. Это внутренняя несогласованность ключа и заявленного диапазона.
2. [Кардашина С.В., Шаньгина Н.В., 2016](https://pedobrazovanie.ru/images/JOURNAL/archive2016/2016-11-5q8c/36.pdf), таблицы 2–6, печатные страницы 219–220: 21A относится к приспособлению; в legacy — к избеганию. Остальные 59 альтернатив совпадают с таблицами при сверке извлеченного текста. Просмотр PDF-изображений через веб-инструмент завершился `Cache miss`; визуальное подтверждение таблиц пока не выполнено.
3. Второй URL из локального ключа — [материал на сайте школы](https://shig.minobr63.ru/wp-content/uploads/2024/06/%D1%82%D0%B5%D1%81%D1%82-%D0%A2%D0%BE%D0%BC%D0%B0%D1%81%D1%81.pdf), страница 3 — также неоднозначен: помещает **30A** в избегание и **21A** в приспособление. Он не совпадает ни с научной публикацией по 30A, ни с текущим ключом по двум альтернативам. Его нельзя автоматически принять за эталон.
4. Пояснение владельца: паспорта обновлялись с задержкой относительно доработок. Исторические документы служат свидетельствами предыдущего состояния; для новых версий нужно восстановить происхождение изменения.

Исходником бланка служит текст, предоставленный владельцем 2026-10-02. Женский вариант по указанной ссылке просмотрен для сверки форм рода; текст сайта не заменяет пользовательский источник. Комбинированные формы рода создают отдельную редакцию бланка. Важны точная редакция, порядок пар и порядок альтернатив A/B внутри пары.

Запуск 2026-10-02: `npm test` завершился с кодом 0; восемь новых тестов успешны, прежняя регрессия также успешна. Внешние fixtures `../upload` по-прежнему отсутствуют. ### Порядок завершения проверки

1. Получить исходную форму/экспорт ее структуры с 30 парами и инструкцией. Текст пар уже получен; полная инструкция еще требует источника.
2. Сопоставить каждую пару и порядок A/B с выбранной документированной редакцией.
3. Установить, какой ключ применим к фактической форме; оформить решение по 21A и при необходимости 30A.
4. Если нужна коррекция, создать новую версию ключа и контрольные протоколы; сохранить legacy для воспроизведения старых расчетов.
5. После сверки разрешить агрегирование для подтвержденной версии. Форму предъявления реализовать отдельной задачей.
