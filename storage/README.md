## Среда и запуск

Проверено 2026-10-02 на Windows: Node.js **22.17.1**, `node:sqlite` / `DatabaseSync`, встроенная SQLite **3.50.0**. Внешние пакеты/сервер не устанавливались. Требуется Node.js >=22.17.1. Драйвер в этой версии экспериментальный: предупреждение не скрывается. Синхронный драйвер выбран для небольшого локального учебного контура, не как производственный стек.

Из корня проекта:

```text
npm run db:migrate
npm run db:seed
npm run db:check
npm run test:storage
npm test
```

- `db:migrate` создает пустую схему, не ответы и не аккаунты входа.
- `db:seed` применяет миграции, импортирует существующий пакет TKI и создает синтетические записи. Повтор не размножает записи и не восстанавливает/перезаписывает измененный черновик.
- `db:check` открывает существующую базу **только для чтения**, проверяет целостность/FK и выводит счетчики без ответов/баллов/личных кодов. Отсутствующую базу не создает.
- Фиксированный файл: `.local/training.sqlite`. Не включается в Git, не обслуживается web-сервером. Нет команды удаления/сброса; существующие чужие базы отвергаются.

В Git — исходники миграций/seed/тестов, **не файл базы**, реальные записи или credentials. CLI не принимает произвольные пути. Серверная конфигурация/резервное копирование — отдельные задачи.

## Физическая схема

13 доменных таблиц соответствуют DATA_MODEL.md; дополнительно `schema_migrations` (номер, SHA-256 SQL, время) и `seed_runs` (версия набора, digest спецификации, manifest созданных UUID).

Таблицы STRICT, обязательные поля явно NOT NULL. На соединении FK включены и проверены; `recursive_triggers=ON` не дает REPLACE обходить DELETE-ограничения. Миграции — одной BEGIN IMMEDIATE транзакцией; при ошибке откатывается весь пакет. Повтор проверяет историю/checksum; примененные миграции не редактируются — добавляются новые с очередным номером. Разрывы нумерации, неизвестная история и несовпадение checksum блокируют запуск. application_id отличает учебный файл, но не защищает от его владельца.

`attempts.group_id/stage_id` — дополнительные связующие поля составных FK, одновременно проверяющие группу/этап enrollment и assignment. `completion_result_id` и `attempt_results.attempt_status` — для двух отложенных взаимных FK: нельзя зафиксировать completed без результата или результат при draft. Перед completed проверяются 30 ответов и input_revision. Завершенные ответы/результат неизменяемы; enrollment/назначение после создания попыток нельзя подменить, включая REPLACE.

Это **ограничения схемы**, не прикладной сервис завершения. SQL не пересчитывает баллы и не доказывает подлинность payload/digest. Серверные проверки прав, expected_revision, содержимого, конкурентного/повторного завершения и вызов неизмененного scoreTki остаются 01д.3/01д.4/01е. Доступ владельца файла не считается защищенным API. Автоматического каскадного удаления и обещания бессрочного хранения нет; разрешенное удаление/сроки — отдельные политика и миграции.

Первый контур допускает только текущий TKI, A/B и demo, не является редактором других методик. В study_memberships только researcher/administrator конкретного исследования; глобальные роли/credentials/сессии не создавались. SQL не проверяет полномочия исполнителя. UUID генерирует Node.js randomUUID; проверка длины в SQL не является полной проверкой формата или авторизацией.

## Выпуск и канонизация

Импорт читает существующие `methods/tki/form.json` и исправленный `keys/1.0.0.json`, не набирает тексты/ключ заново. Выпуск хранит полную каноническую копию формы и 30 пунктов. Ключ остается в файле репозитория; digest использует **прежний** порядок `{id,items,type,scales}` обработчика. Полная методика все еще draft, проверен только ключ; неправильная версия не импортируется.

canonical-json-v1: ключи объектов сортируются JS .sort(), порядок массивов сохраняется, примитивы — JSON.stringify, SHA-256 считается в UTF-8. Тексты/Unicode/пробелы не нормализуются. Form_digest охватывает **весь исходный JSON**, включая instruction, source_text и provenance. Значения вне JSON отвергаются.

Текущий form_digest: `sha256:10ea2173315f8c74091ec7f619fba7fe8d0ccfa005330cee8720054332daaad7`.

Responses_digest берет только item_id/value в порядке переданного упорядоченного списка пунктов выпуска. Дубликаты, неизвестные пункты и неканонические A/B отвергаются; пропуск не заменяется A/нулем. Digest — **не обезличивание**. Функция не означает, что результаты уже сохраняются через API.
