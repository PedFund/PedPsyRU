# 01е — завершение и сохраненный учебный результат

Дата: 2026-10-03. Реализация продолжена автономно по синхронизированным AGENTS.md/ROADMAP.md в той же codex/participant-drafts / [PR #7](https://github.com/PedFund/PedPsyRU/pull/7), без еще одной зависимой ветки. Код не интегрирован в main. Только вымышленные локальные данные; научное утверждение полной методики/инструкции не подменяется техническими тестами.

## Реализованный небольшой блок

`storage/completion.js`: существующая индивидуальная сессия/доступность → BEGIN IMMEDIATE и повторная проверка → expected_revision → закрепленный выпуск → полный сохраненный снимок → прежний scoreTki → один attempt_results + completed/revision+1 + обязательный аудит → commit. Ответы не принимаются в операции завершения, не меняются и не копируются в T1/T2. Новая миграция не нужна.

`POST /api/participant/attempts/:id/complete` принимает только `{"expected_revision":2}`, максимум 2048 байт JSON; Origin и session-bound X-CSRF-Token обязательны. Только свой доступный протокол участника. Без сессии — 401; чужой/недоступный ID — одинаковый 404; invalid/лишние поля — 400; stale draft revision — 409; неполнота — 422 INCOMPLETE_RESPONSES; отказ вычислителя — 422 SCORING_REJECTED; несовпадение пакета выпуска — 503 RELEASE_UNAVAILABLE; технический сбой — generic 500. Неполный/blocked/error протокол остается draft без результата. Клиентские версии, роль, study, ответы и баллы не принимаются.

Полный протокол упорядочивается по release_items.ordinal. Сервер сверяет форму/снимок/form_digest/key_digest/состояние проверки с поддерживаемым пакетом; вычислитель проверяет версии и ключ. Сохраняются полный payload прежнего контракта, input_revision, canonical responses_digest, точные версии/ключ digest, серверное время. Result UNIQUE(attempt_id), взаимные отложенные FK и проверка revision схемы дополняют транзакционный сервис. Ошибка результата, перевода status или аудита откатывает все; completed без result не фиксируется.

Повтор на completed с валидным телом возвращает **тот же** сохраненный result_id/payload/время/digest без нового расчета или записи, независимо от старой expected_revision. Доступ и CSRF по-прежнему проверяются. Результат не пересчитывается по измененному текущему пакету при чтении/повторе. Это идемпотентность завершения, а не разрешение повторного обследования.

`GET /api/participant/attempts/:id/result` возвращает `{completion}`: demo/persistence=true, attempt/status/revision/release/form, result_id/input_revision/responses_digest/calculated_at, полный `result`. Draft — 409 RESULT_NOT_READY. Выдаются только собственные пять сырых показателей; ключ, тексты, ответы, credentials и токены не выдаются. Digest — не анонимизация; исследовательского/staff result API этим блоком не добавлено. Метаданный аудит обязателен перед выдачей, без баллов/ответов/digest/секретов. Без настроенного completion-сервиса маршрут закрыт (404).

## Интерфейс

Последняя пара `/take`: проверка пропусков → подтверждение необратимости → блокировка повторного нажатия/изменений → ожидание очереди записи → POST с последней подтвержденной revision. Сервер считает только сохраненные ответы. После успеха — readonly протокол и пять сырых шкал, без уровней/норм/психологического заключения, с предупреждением о проверенном ключе и еще проверяемой полной инструкции.

Reload и новый login восстанавливают сохраненный результат через собственный GET. Нет localStorage ответов/результатов, выгрузки участником и публичного result URL. При неопределенном исходе завершения запись блокируется: сначала явная загрузка сервера; сервер мог уже завершить попытку. Конфликты/отзыв/CSRF не обходятся. Исходный `/` и stateless `/api/score` остаются отдельной несохраняемой демонстрацией.

## Проверки

`npm run test:completion`: **15/15**. Полная регрессия `npm test`: **134/134** = 15 новых + 119 прежних. Проверены:

- пять баллов по независимому контрольному ключу, версии, reversed input → canonical digest;
- неполнота, strict body/лишние поля/подмена score/version/scope/role, stale revision;
- параллельные POST → один ID и результат; потерянный ответ → GET/повтор того же результата;
- гонка draft save/complete → только одна revision выигрывает, нет рассогласования;
- completed нельзя изменить/очистить; same/cross study/нет входа/staff-токены не читают и не завершают чужой результат;
- Origin/CSRF/content type/body/query/method bounds; отзыв/исключение/закрытое назначение на каждом запросе;
- SQL/mandatory audit failure → rollback, затем безопасный повтор; audit failure чтения → нет баллов в ответе;
- blocked/error/throw/неверная версия вычислителя; test-only corruption выпуска → отказ, не молчаливый новый пакет;
- файл закрыт/открыт и новый login → тот же result, scorer заглушкой запрещен, нет перерасчета/дубликата.

Браузер: отдельная временная in-memory база, 29 синтетических A/q30 → неполнота не завершается → 30-й A сохраняется → отмена подтверждения → подтвержденное завершение → 5×6/12; radios/reset заблокированы, просмотр предыдущей пары работает. Reload и logout/login → тот же attempt и calculated_at, те же шкалы, T1/T2 не завершены. Один result/completed непосредственно проверены service/HTTP тестами; браузер подтверждает видимое завершение T0 и отсутствие завершения T1/T2, не независимый запрос к счетчикам базы. После проверки logout, helper закрыт, основной 4173 перезапущен. Скриншот сохранен вне Git. Основная база не используется для этих изменений; domain SHA-256 до/после одинаков, 18 attempts/4 responses/0 results, credentials/sessions=0, integrity/FK ok.

Готовность: серверное завершение/свой учебный raw result подтверждены указанными проверками. Не независимый security audit, не production/реальный набор и не утвержденная интерпретация. Полная mobile/browser/offline матрица и аппаратные аварии не проверялись. Форма/ключ/математика и миграции неизменны.
