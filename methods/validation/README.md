# Контроль комплектности пакетов PsyTests

**Единый источник кода:** [репозиторий PedFund/PedPsyRU](../../README.md). Этот каталог описывает один повторяемый процесс, а не вторую библиотеку. Существующие [methods/README.md](../README.md), манифесты, версии и runtime остаются источниками истины.

## Исходные материалы

Входной набор: папка Google Drive `MD-keys/psytests-method-packages`, 40 Markdown-пакетов и README. Два пакета ЦО-36 и два пакета FFMQ относятся к двум группам, но используют одну семью ключей. Таким образом, номинально представлены 38 уникальных методик/версий.

Google Drive: https://drive.google.com/drive/folders/1viIz6Rj4Rns-1VBUZsndmpE1H29-IrdE

**Оригинальные тексты, ключи и стимулы не дублируются в новом каталоге GitHub.** Перед использованием в коммерческой/публичной платформе проверить право воспроизведения и распространения. Если появится право импорта, закрепить версионированные исходники и SHA-256 в разрешенном хранилище. Не хранить учетные данные, персональные ответы и результаты в Git.

## Запуск

После законного локального получения папки с Markdown:

```bash
node scripts/validate-psytests-packages.js ./psytests-method-packages --out ./psytests-validation-report.json
node --test tests/psytests-package-validator.test.js
```

При наличии блокирующих ошибок первая команда завершится с кодом 1; отчет все равно будет записан. Этот JSON является **производным отчетом**, а не единственным источником данных. Его можно воспроизвести повторно из тех же исходников. Путь и содержимое входной папки остаются неизменными.

## Что проверяется

- Девять обязательных разделов в пакете.
- Число и последовательность нумерованных пунктов раздела «Стимульный материал».
- Признаки непроверенного ключа, внешнего ключа и нерешенного соответствия шкалы ответа.
- Предупреждения о нормах, ответах, совпадающих семьях ключей.
- Контрольная классификация: `structure_valid` и `technically_importable`.

## Что валидатор НЕ доказывает

- Он не сверяет текст с авторским первоисточником и не подтверждает права использования.
- Он не извлекает математические формулы из произвольного YAML и не проверяет их правильность.
- Он не проверяет достаточность норм для конкретной группы.
- Он не запускает обработчики, не подключает методики к серверному allowlist и не изменяет БД.
- `technically_importable=true` означает только отсутствие предусмотренных структурных блокировок; это **не разрешение на публикацию**, не сквозная интеграция и не научная приемка.

## Следующий обязательный этап

Прежде чем подключать очередную партию, создать версионированный машинный контракт (JSON) на основе [METHOD_EXTENSION_CONTRACT.md](../../METHOD_EXTENSION_CONTRACT.md), с явным полем для преобразования UI-ответов в баллы. Для каждой методики зафиксировать контрольные векторы и ожидаемые результаты. Только после независимой проверки подключать выбранный выпуск через существующий реестр/адаптер. Не вводить непроверенные формулы и нормативные уровни.

Для 11 методик пилота Issue №75 этот этап начат в [`pilot-11/`](pilot-11/README.md): там отдельно отмечены подтвержденные расчетные контракты, существующие пакеты и формы, которые нельзя считать готовыми до переноса владельческих источников.

## Устойчивость процесса

Не начинать повторный поиск форм с нуля. Начинать с этой папки, [methods/README.md](../README.md) и существующих манифестов. Все доработки оформлять коммитом и PR; `main` и текущие учебные выпуски не менять без прохождения CI и согласования Merge.
