# Пилотные 11 методик — техническая подготовка Issue №75

Этот каталог — проверяемая **staging-матрица**, а не второй runtime-реестр и не разрешение на назначение методик. Научно-методические решения зафиксированы в Issue №69. Ветка не меняет серверный allowlist, PostgreSQL, существующие выпуски, ответы или результаты.

## Что проверяется

- ровно 11 записей с отдельными статусами формы, расчета и пакета;
- полное покрытие индексов в восьми новых декларативных расчетных контрактах;
- обязательность всех ответов, допустимые значения, прямое/обратное кодирование;
- крайние и пороговые значения утвержденных рабочих уровней;
- отсутствие округления в сохраняемых значениях PVQ-RR и ШОКЖ;
- отсутствие выдуманных норм TTF/ATF;
- неизменность массива первичных ответов при расчете;
- сохранение действующего пакета TKI и необходимость отдельной новой версии нормы Карпова.

Запуск:

```bash
node scripts/validate-pilot-11.js
node --test tests/pilot-11-packages.test.js
```

## Явные границы

- Тексты из Google Drive не дублируются автоматически: PR №73 установил этот режим до решения о праве хранения и публикации.
- Формы Моткова, Рифф, PVQ-RR и TTF/ATF, переданные только в чат/файлах владельца, нельзя восстанавливать по памяти или открытым похожим версиям.
- ШОКЖ в PR №72 содержит прежнее решение об обратном пункте 28. Issue №69 его отменяет; данный staging-контракт фиксирует 28 как прямой, но не переписывает чужую ветку.
- Исправленная таблица Карпова не заменяет `methods/karpov/norms-local.json` и исторический выпуск.
- Расчеты здесь предназначены для синтетической проверки. Они не подключены к каталогу и не создают доступ researcher к первичным ответам.

## Runtime-допуск по Issue №77

Серверная матрица `src/application/pilot-method-readiness.ts` показывает эти 11 строк только суперадминистратору через защищённый раздел «Перенос методик». Матрица не является обходом allowlist: отсутствие полного закреплённого бланка, ключа или документированного права использования оставляет выпуск недоступным исследователю.

На текущей доказательной базе из пилотных 11 технически назначается только ранее существовавший учебный выпуск TKI `1.0.0`. Это не означает готовность TKI к реальному пилоту: правовой статус по-прежнему не документирован. Ни один новый staging-контракт из этого каталога не опубликован и не добавлен в runtime/БД.
