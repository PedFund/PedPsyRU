# Административный просмотр и скачивание — 01д.3б

Дата: 2026-10-02. Только локальный синтетический контур, не production и не прием реальных обследований.

## Требование и реализованные границы

Владелец утвердил **доступ обеих ролей ко всем исследованиям**. Администратор — менеджер исследователей: просмотр, контроль, скачивание; не занимается обработкой/дополнением методик. Суперадминистратор — менеджер исследователей и методик. Назначение staff конкретному исследованию не требуется. Закрытые исследования/группы/этапы и исключенные участники не скрываются от административного контроля.

В этом небольшом блоке реализованы вход, просмотр исследований/протоколов/первичных ответов, скачивание. Управление исследователями и редактор методик **еще не реализованы**: roles.js отделяет policy-права от implemented_permissions. Только superadministrator имеет policy methods.manage; administrator — нет. Ни одна роль этого кабинета не редактирует ответы и не запускает обработку сохраненного протокола. Прежний stateless /api/score остается технической проверкой вымышленного бланка, не административным сервисом обработки.

## Вход и безопасность

Переиспользуются crypto primitives участника: scrypt N=131072/r=8/p=1/dk64, maxmem 160 MiB, случайная соль 16 байт; timingSafeEqual и дорогая проверка неизвестного кода. Пароль 12+ символов, максимум 256 UTF-8 байт, без обрезания. Учетная запись/роль определяется сервером; login body — строго login_id/password, без роли/области.

Staff sessions отделены от participant: случайный токен 32 байта, в SQLite только SHA-256; cookie pedpsy_staff_session — host-only HttpOnly SameSite=Strict, TTL 30 минут, idle 10 минут. Роль и user status перепроверяются, reset/revoke/version/disabled немедленно закрывают последующие запросы. Async hash завершается повторной проверкой credential: отзыв во время hash не создает сессию. Staff token не работает в participant realm и наоборот, даже если переименовать cookie. Study researcher membership не дает staff-права.

Cookie без Secure допустима здесь только из-за HTTP-loopback, **не шаблон для production**. Host/Origin/Sec-Fetch-Site защиты унаследованы; Origin обязателен на login/logout, logout требует session-bound CSRF. Ограничения сохраняются в SQLite: общий бюджет 30 входов/5 минут, отдельный staff-login bucket 5/15 минут; один async derive на staff service. Клиентский флаг/URL/header/Bearer не расширяет доступ.

Аудит append-only, содержит время, credential_id/role, action/outcome/reason, resource_id/record_count. Не содержит выбранных ответов, текстов, баллов, паролей/токенов. Перед выдачей выгрузки запись аудита обязательна; отказ аудита возвращает 500 без вложения. Неизменяемость не утверждает бессрочное хранение. Доступ владельца локального файла/компьютера не защищается HTTP-ролями; шифрование файла, backup, юридические основания и независимая безопасность — отдельные задачи.

## HTTP и JSON-экспорт

| Маршрут | Назначение |
|---|---|
| POST /api/admin/auth/login | Общий вход обеих ролей по серверному credential |
| GET /api/admin/auth/session | Подтвержденная роль, all_studies, implemented/planned permissions, CSRF |
| POST /api/admin/auth/logout | Отзыв текущей staff-сессии |
| GET /api/admin/studies | Все учебные исследования, статусы и счетчики |
| GET /api/admin/attempts?offset=0&limit=50 | Все попытки, пагинация (1–100 записей), статусы/версии/число ответов |
| GET /api/admin/attempts/:id | Протокол с 30 парами и первичными A/B/null |
| GET /api/admin/attempts/:id/answers.json | Защищенное скачивание одного протокола |
| GET /api/admin/answers.json | Защищенное скачивание всех протоколов |

GET требует действующей staff-cookie. Query допускается только для offset/limit списка, без дублей/клиентского scope/role. Анонимный запрос — 401, отсутствующий ID — одинаковый 404, неподдержанный метод — 405; manager/process endpoints отсутствуют. API/статика no-store/nosniff, ошибки не эхо запросов. Content-Disposition имеет фиксированное безопасное имя, нет публичного каталога выгрузок или токена в URL.

Выбран JSON **pedpsy-primary-answers-1.0**: demo, UTC generated_at, scope, protocol_count, protocols. Для каждой попытки — исследование/участник-код/группа/этап, состояния, revision/current_item_id, release_id и точные версии формы/методики/обработчика/контракта. Items упорядочены по ordinal закрепленного release_items; содержат номер/ID, отображаемые value/label/text двух вариантов, выбранный value. Пропуск — null + missing_item_ids, не ноль/A. Пустые черновики тоже экспортируются. Ключ, source_text, hashes/секреты, баллы/интерпретации не включаются; расчет не вызывается.

Общая выгрузка — синхронный транзакционный снимок; лимит стенда **500 протоколов и 4 MiB UTF-8**. При превышении — HTTP 413 EXPORT_LIMIT, не частичный «все». В браузере ссылки используют нативное защищенное вложение; если сервер отказывает, браузер может показать/сохранить JSON-ошибку, которую нельзя считать выгрузкой. Большие пакеты/потоковая выдача/CSV/XLSX требуют отдельной задачи. Отдельный протокол можно скачивать независимо от лимита числа общих записей. Файл остается на устройстве после logout; его хранение — ответственность получателя, это отмечено в UI.

## Как выдать локальный вымышленный вход

В **своем интерактивном терминале** из корня репозитория:

```text
npm run staff:issue -- administrator PLATFORM-ADMIN
npm run staff:issue -- superadministrator PLATFORM-SUPERADMIN
```

CLI покажет персональный случайный пароль один раз; затем открыть http://127.0.0.1:4173/admin. Нет общего пароля и автоматического повышения researcher. Повтор issue не перезаписывает credential/ответы. Пароль нельзя передавать аргументом/URL или сохранять в репозиторий. Неинтерактивная команда отказывается до записи в базу.

```text
npm run staff:reset -- PLATFORM-ADMIN
npm run staff:revoke -- PLATFORM-ADMIN
```

Reset выдаст новый случайный пароль и отзовет сессии; revoke блокирует доступ, не удаляет обследования. Роль credential фиксирована, изменение роли требует отдельного решения/процедуры. В основном файле во время реализации staff credentials не выдавались.

## Выполненные проверки

`npm test`: **97/97**, включая 21 staff + 23 participant + 22 storage + 31 прежний. Проверены обе роли/все исследования без membership, закрытые/excluded записи, отсутствие ключей/секретов/баллов в JSON, точные A/B/null/версии, неаутентифицированный доступ, realm/token/header/body подмена, SQL identity/FK/REPLACE, reset/revoke/disabled/version, async revocation race, idle/absolute/backward-time, limiter/Origin/CSRF, пагинация/неразрешенные query, missing ID/audit, отсутствие mutation/process/manager API, отказ без настроенного сервиса и non-TTY CLI. Batch сверх 500 отвергается целиком; аудит отказа сохраняется. Эти тесты не доказывают научную валидность TKI.

Браузер: временная in-memory база, отдельные синтетические staff-аккаунты, не основной SQLite. Администратор login → оба исследования/18 протоколов → просмотр A/B/28 пропусков → reload → выгрузка всех; скачанный JSON действительно содержит 18 протоколов двух исследований. Logout → суперадминистратор login → просмотр T0 второго исследования → скачивание одного; файл сверили (A/B/null, 28 пропусков) → reload сохраняет роль/общую область → logout. Первую blob-реализацию заменили обычным HTTP-вложением и перепроверили реальный скачанный файл. Скриншот вне Git. Полная мобильная/межбраузерная матрица не выполнена.

На основной базе применена только 003: hash снимка доменных таблиц до/после одинаков, 2 исследования/18 попыток/4 ответа/0 результатов сохранены. Credentials и sessions обеих областей — 0; integrity/FK — ok. Сервер 4173 перезапущен, /admin доступен; прежний бланк/ключ/вычислитель не изменялись.
